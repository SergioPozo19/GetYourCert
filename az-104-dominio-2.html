Preguntas de ejemplo del dominio 2

8 preguntas de nuestro banco de 104 para este dominio. Intenta responder antes de ver la solución.

1. Un administrador regenera (rota) la clave de acceso principal de una cuenta de almacenamiento. ¿Qué efecto tiene esto sobre las SAS de tipo 'Service SAS' generadas previamente con esa clave?

  1. Las SAS se regeneran automáticamente con la nueva clave sin interrupción del servicio
  2. No tiene ningún efecto sobre las SAS existentes, que seguirán siendo válidas indefinidamente
  3. Todas las SAS de servicio firmadas con esa clave dejan de ser válidas inmediatamente
  4. Solo afecta a las SAS de delegación de usuario, no a las firmadas con claves de cuenta
Ver respuesta

Respuesta correcta: C. Las SAS de cuenta y de servicio se firman con una clave de acceso de la cuenta de almacenamiento; si esa clave se regenera, todas las SAS firmadas con la clave antigua quedan invalidadas inmediatamente, lo que es útil para revocar accesos comprometidos.

2. Tu empresa quiere que los usuarios accedan a recursos compartidos de Azure Files mediante sus credenciales corporativas de Active Directory local, conservando los permisos NTFS a nivel de archivo y carpeta. ¿Qué función de Azure Files permite esto?

  1. Cifrado del lado del servidor con claves administradas por el cliente, almacenadas en Azure Key Vault
  2. Autenticación basada en identidad para SMB mediante Active Directory Domain Services (AD DS) o Microsoft Entra Kerberos
  3. Replicación con redundancia de zona (ZRS), que distribuye copias entre zonas de disponibilidad
  4. Firmas de acceso compartido (SAS) generadas individualmente para cada usuario del recurso compartido
Ver respuesta

Respuesta correcta: B. Azure Files admite autenticación basada en identidad mediante AD DS local (o Microsoft Entra Kerberos), permitiendo a los usuarios autenticarse con sus credenciales de dominio y aplicar permisos NTFS a nivel de directorio y archivo.

3. ¿Qué rol RBAC integrado debería asignarse a una aplicación que necesita leer y escribir datos en contenedores de blobs mediante Microsoft Entra ID, pero no debe poder gestionar la configuración de la cuenta de almacenamiento?

  1. Storage Blob Data Contributor
  2. Propietario (Owner)
  3. Lector (Reader)
  4. Colaborador (Contributor) a nivel de cuenta de almacenamiento
Ver respuesta

Respuesta correcta: A. Los roles 'Storage Blob Data *' (Reader, Contributor, Owner) controlan el acceso a los datos dentro de blobs vía Microsoft Entra ID, separados de los roles de gestión del recurso (como Colaborador), que controlan la configuración de la cuenta pero no necesariamente el acceso a los datos.

4. Un contenedor de blobs tiene su nivel de acceso público configurado como 'Privado (sin acceso anónimo)'. Un usuario intenta descargar un blob usando solo la URL pública, sin token SAS ni autenticación. ¿Qué ocurre?

  1. La solicitud se rechaza con un error de autorización
  2. La descarga funciona porque las URL de blobs siempre son accesibles
  3. Funciona solo si el blob está en la capa Hot
  4. Funciona solo durante los primeros 30 días tras la creación del blob
Ver respuesta

Respuesta correcta: A. Cuando el nivel de acceso público de un contenedor es 'Privado', cualquier solicitud anónima sin credenciales válidas (clave, SAS o token de Microsoft Entra ID) es rechazada.

5. ¿Cuál es el período máximo de validez de una SAS de delegación de usuario en Azure Blob Storage?

  1. 7 días
  2. 30 días
  3. 1 año
  4. 10 años
Ver respuesta

Respuesta correcta: A. Una SAS de delegación de usuario tiene un período máximo de validez de 7 días. Se firma con credenciales de Azure AD (no con la clave de cuenta), lo que la hace más segura que una SAS de cuenta o de servicio. Requiere que el principal tenga el rol 'Storage Blob Data Contributor' o superior en el ámbito correspondiente.

6. Una empresa necesita el menor coste posible de almacenamiento para datos que se acceden con mucha frecuencia y requieren baja latencia. ¿Qué combinación de tipo de redundancia y capa de acceso es más adecuada?

  1. ZRS con capa de acceso Archive
  2. GZRS con capa de acceso Archive
  3. RA-GRS con capa de acceso Cool
  4. LRS con capa de acceso Hot
Ver respuesta

Respuesta correcta: D. Para datos de acceso frecuente, la capa Hot ofrece el menor coste de acceso (aunque mayor coste de almacenamiento por GB); combinarla con LRS minimiza además el coste de redundancia frente a opciones georredundantes, si no se requiere protección ante fallo regional.

7. Una empresa debe garantizar que ningún blob en un contenedor específico pueda ser eliminado o modificado durante un período de auditoría de 5 años. ¿Qué configuración deben aplicar?

  1. Habilitar el control de versiones de blobs con retención de 5 años
  2. Aplicar una directiva de retención basada en tiempo bloqueada (locked) con 5 años en el contenedor
  3. Configurar una directiva de ciclo de vida que mueva los blobs al nivel de archivo después de 5 años
  4. Habilitar la eliminación temporal de blobs con un período de retención de 5 años
Ver respuesta

Respuesta correcta: B. Para garantizar que los blobs no puedan ser eliminados ni modificados durante un período específico, se debe aplicar una directiva de retención basada en tiempo WORM (Write Once, Read Many) en estado 'bloqueado'. Una vez bloqueada, la directiva es inmutable y no puede acortarse. El control de versiones y la eliminación temporal permiten recuperar datos borrados, pero no impiden la eliminación. Las directivas de ciclo de vida gestionan el movimiento entre niveles, no la inmutabilidad.

8. ¿Cuál es la diferencia entre la eliminación temporal de blobs (blob soft delete) y la eliminación temporal de contenedores (container soft delete) en Azure Storage?

  1. Solo la eliminación temporal de contenedores puede restaurar blobs y snapshots eliminados; la de blobs no conserva los snapshots huérfanos
  2. La eliminación temporal de blobs protege blobs individuales y snapshots; la eliminación temporal de contenedores protege el contenedor completo y todos los blobs en él
  3. La eliminación temporal de contenedores requiere cuenta Premium con LRS, mientras que la de blobs funciona en cuentas GPv2 con cualquier replicación
  4. Ambas características son equivalentes técnicamente pero se facturan a diferente precio por GiB de datos retenidos en estado eliminado
Ver respuesta

Respuesta correcta: B. La eliminación temporal de blobs protege blobs de bloques, blobs de páginas y snapshots individuales de la eliminación accidental. La eliminación temporal de contenedores protege el contenedor completo junto con todos los blobs que contiene. Ambas características pueden habilitarse simultáneamente y tienen períodos de retención configurables independientemente. Son complementarias y no exclusivas.

AZ-900 · Dominio 2 de 3 · 35-40% del examen

Descripción de la arquitectura y los servicios de Azure

El dominio 2 de AZ-900 supone entre el 35 y el 40% del examen, el de más peso del temario. En EarnYourCert tienes 183 preguntas originales de este dominio, todas con explicación: 115 de opción múltiple, 37 de sí o no y 31 de completar u ordenar, como en el examen real.

Qué entra en este dominio

  • Regiones, pares de regiones y zonas de disponibilidad
  • Grupos de administración, suscripciones y grupos de recursos
  • Proceso: máquinas virtuales, conjuntos de escalado, App Service, contenedores y Functions
  • Redes: VNet, emparejamiento, VPN Gateway y ExpressRoute
  • Almacenamiento: niveles de acceso y redundancia (LRS, ZRS, GRS, GZRS)
  • Identidad: Microsoft Entra ID, MFA, acceso condicional y Confianza cero

Preguntas de ejemplo del dominio 2

8 preguntas de nuestro banco de 183 para este dominio. Intenta responder antes de ver la solución.

1. Una empresa multinacional planea desplegar su aplicación en una región de Azure que ofrece zonas de disponibilidad. ¿Cuántas zonas de disponibilidad como mínimo suele tener una "región con zonas de disponibilidad" en Azure?

  1. Al menos diez
  2. Exactamente una
  3. Al menos tres
  4. Exactamente dos
Ver respuesta

Respuesta correcta: C. Una región considerada "con zonas de disponibilidad" en Azure ofrece como mínimo tres zonas independientes, cada una con su propia alimentación, refrigeración y red, lo que permite distribuir cargas de trabajo de forma resiliente. Una sola zona no proporcionaría redundancia entre zonas. Dos zonas no son suficientes para el modelo de tolerancia a fallos que Azure define para estas regiones. Diez es un número mucho mayor del que ofrece cualquier región actualmente.

2. Una empresa tiene una jerarquía de grupos de administración con un grupo "Producción" y otro "No-Producción". Un administrador mueve una suscripción del grupo "No-Producción" al grupo "Producción". ¿Qué efecto tiene este cambio sobre las políticas y permisos heredados?

  1. La suscripción conserva permanentemente las políticas y permisos de ambos grupos simultáneamente
  2. La suscripción debe eliminarse y volver a crearse para que se apliquen las nuevas políticas
  3. El cambio de grupo de administración no afecta a ninguna política ni permiso, ya que estos se asignan únicamente a nivel de recurso
  4. La suscripción deja de heredar las políticas y permisos del grupo "No-Producción" y empieza a heredar los del grupo "Producción"
Ver respuesta

Respuesta correcta: D. La herencia de políticas y permisos en la jerarquía de grupos de administración sigue la posición actual de la suscripción; al moverla a un nuevo grupo, deja de heredar las del grupo anterior y empieza a heredar las del nuevo grupo. No conserva ambas de forma permanente, las políticas se pueden asignar a distintos niveles (no solo a recursos individuales), y no es necesario eliminar y recrear la suscripción para que el cambio surta efecto.

3. Una empresa tiene una suscripción de Azure y quiere asegurarse de que, antes de poder crear recursos de tipo "Microsoft.Sql/servers", la plataforma reconozca y habilite ese tipo de recurso en la suscripción. ¿Qué proceso describe esto?

  1. La transferencia de la suscripción a un nuevo grupo de administración
  2. El registro del proveedor de recursos correspondiente en la suscripción
  3. La asignación de una etiqueta de tipo "SQL" a la suscripción
  4. La creación de una nueva zona de disponibilidad para esa suscripción
Ver respuesta

Respuesta correcta: B. Antes de poder usar los tipos de recursos de un servicio, su proveedor de recursos (en este caso "Microsoft.Sql") debe estar registrado en la suscripción; muchos proveedores se registran automáticamente, pero algunos requieren registro manual. Las zonas de disponibilidad son ubicaciones físicas no relacionadas con el registro de servicios. Las etiquetas son metadatos descriptivos sin efecto funcional. Cambiar de grupo de administración afecta a la gobernanza, no al registro de proveedores de recursos.

4. ¿Cuál es la diferencia principal entre una dirección IP pública y una dirección IP privada en Azure?

  1. Ambas direcciones son accesibles desde Internet por igual
  2. La IP pública solo puede usarse en máquinas virtuales Spot
  3. La IP privada se factura el doble que la pública
  4. La IP pública es accesible desde Internet; la privada no
Ver respuesta

Respuesta correcta: D. Una dirección IP pública permite que un recurso sea accesible desde Internet, mientras que una dirección IP privada solo permite la comunicación dentro de la red virtual o redes conectadas a ella.

5. Una empresa tiene aplicaciones desplegadas en Azure y en su centro de datos local, y quiere que las solicitudes de los usuarios se enrutan al endpoint con mejor rendimiento (menor latencia) según la ubicación del usuario, a nivel de resolución de nombres. ¿Qué servicio de Azure encaja mejor?

  1. Azure Traffic Manager con enrutamiento por rendimiento
  2. Azure Virtual Network NAT Gateway para traducción de direcciones de red salientes
  3. Azure Service Bus para mensajería asíncrona entre componentes desacoplados
  4. Azure Bastion para acceso seguro a máquinas virtuales sin IP pública
Ver respuesta

Respuesta correcta: A. Azure Traffic Manager es un balanceador de tráfico basado en DNS que puede dirigir a los clientes hacia el endpoint con menor latencia según su ubicación geográfica, funcionando tanto con endpoints en Azure como fuera de Azure (incluido on-premises). Azure Bastion proporciona acceso remoto seguro a VMs, no enrutamiento de tráfico de aplicaciones. El NAT Gateway gestiona la traducción de direcciones de salida, no el enrutamiento de entrada basado en rendimiento. Azure Service Bus es un servicio de mensajería, no de enrutamiento de tráfico de red.

6. Un desarrollador escribe una función en Azure Functions que debe ejecutarse automáticamente cada vez que se sube un nuevo archivo a un contenedor de Blob Storage, sin necesidad de sondear el almacenamiento periódicamente. ¿Qué elemento de Azure Functions hace posible esta ejecución automática?

  1. Una zona de disponibilidad
  2. Un disparador (trigger) de Blob Storage
  3. Un grupo de seguridad de red
  4. Un emparejamiento de redes virtuales
Ver respuesta

Respuesta correcta: B. Un disparador (trigger) en Azure Functions define el evento que provoca la ejecución de la función; el disparador de Blob Storage hace que la función se ejecute automáticamente cuando se crea o modifica un blob, sin necesidad de sondeo manual. Una zona de disponibilidad es una ubicación física de centros de datos. Un grupo de seguridad de red filtra tráfico de red. El emparejamiento de redes virtuales conecta VNets; ninguno de estos provoca la ejecución de funciones.

7. ¿Qué tipo de blob de Azure Storage está optimizado para operaciones de adición rápida, como archivos de registro a los que se añaden datos continuamente?

  1. Blob de archivo (archive blob)
  2. Blob en bloques (block blob)
  3. Blob en páginas (page blob)
  4. Blob de anexado (append blob)
Ver respuesta

Respuesta correcta: D. Los blobs de anexado (append blobs) están optimizados para operaciones de adición, lo que los hace ideales para escenarios como el registro de datos donde se añade información continuamente al final del archivo.

8. Un empleado introduce su nombre de usuario y contraseña para iniciar sesión en una aplicación. El sistema verifica que esas credenciales son correctas y corresponden a un usuario registrado. ¿Qué proceso de seguridad describe esta acción?

  1. Gobernanza de datos
  2. Autenticación
  3. Cifrado en tránsito
  4. Autorización
Ver respuesta

Respuesta correcta: B. La autenticación es el proceso de verificar que un usuario es quien dice ser, normalmente mediante credenciales como nombre de usuario y contraseña. La autorización es un paso posterior que determina qué puede hacer ese usuario ya autenticado. El cifrado en tránsito protege los datos mientras viajan por la red, sin relación con la verificación de identidad. La gobernanza de datos se refiere a las políticas de gestión de datos, no a la verificación de identidad de un usuario.

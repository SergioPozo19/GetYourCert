Administrar y mantener dispositivos

El dominio 2 de MD-102 supone entre el 25 y el 30% del examen, el de más peso del temario. En EarnYourCert tienes 188 preguntas originales de este dominio, todas con explicación: 127 de opción múltiple, 31 de sí o no y 30 de completar u ordenar, como en el examen real.

Preguntas de ejemplo del dominio 2

8 preguntas de nuestro banco de 188 para este dominio. Intenta responder antes de ver la solución.

1. ¿Qué información debe contener el archivo CSV que se importa para registrar dispositivos en el servicio Windows Autopilot?

  1. Nombre del dispositivo, usuario asignado como propietario principal y contraseña de la cuenta de administrador local del dispositivo
  2. Hash de hardware del dispositivo, número de serie y (opcionalmente) identificador de pedido y etiqueta de grupo de Autopilot
  3. Dirección IP actual del dispositivo, nombre del equipo en el dominio y contraseña de recuperación de BitLocker almacenada en Entra ID
  4. Número de licencia de Windows activo, número de serie del dispositivo físico y fecha exacta de compra al fabricante u OEM
Ver respuesta

Respuesta correcta: B. El CSV de Autopilot contiene: hash de hardware (identificador único del dispositivo), número de serie, identificador del pedido (opcional) y etiqueta de grupo (opcional). El hash se genera con Get-WindowsAutoPilotInfo.

2. Los dispositivos de Autopilot unidos a Microsoft Entra ID deben llamarse con el prefijo CTS- seguido del número de serie. ¿Dónde lo configura?

  1. En una regla de grupo dinámico que renombra por número de serie
  2. En la plantilla de nombre de dispositivo del perfil de implementación
  3. En la página de estado de inscripción con un mensaje personalizado
  4. En una directiva de cumplimiento que comprueba el nombre de cada equipo
Ver respuesta

Respuesta correcta: B. Para la unión a Entra, la opción 'Aplicar plantilla de nombre de dispositivo' del perfil de implementación de Autopilot admite macros como %SERIAL% y %RAND:x% (por ejemplo, CTS-%SERIAL%), con un límite de 15 caracteres.

3. Quieres crear un perfil de configuración de Intune para dispositivos macOS que configure el servidor de correo corporativo. ¿Qué tipo de perfil debes crear?

  1. Restricciones de dispositivos
  2. Correo electrónico
  3. Certificado SCEP
  4. VPN
Ver respuesta

Respuesta correcta: B. El tipo de perfil 'Correo electrónico' permite configurar cuentas de correo en dispositivos móviles y de escritorio, incluyendo el servidor, el protocolo (Exchange ActiveSync, etc.) y las credenciales.

4. Antes de pasar a Intune, quiere saber qué opciones de sus GPO actuales tienen equivalente en MDM. ¿Qué herramienta debe usar?

  1. Análisis de directivas de grupo con un XML de copia de GPO
  2. Informes de rendimiento de inicio de Endpoint analytics por modelo
  3. Evaluaciones de Microsoft Purview Compliance Manager
  4. El informe de cumplimiento de Windows Update para empresas
Ver respuesta

Respuesta correcta: A. El análisis de directivas de grupo importa archivos XML de copias de GPO, muestra qué opciones se admiten en MDM y puede migrar las compatibles a un perfil del catálogo de configuración.

5. ¿Qué permite hacer Microsoft Intune Advanced Analytics que es imposible con los informes estándar de Intune?

  1. Ver la lista completa de todos los dispositivos inscritos en Intune con su estado de inscripción actual y la fecha y hora de la última sincronización
  2. Predecir posibles fallos de hardware con tendencias de telemetría y ejecutar consultas KQL en tiempo real
  3. Crear informes de rendimiento de dispositivos completamente personalizados con Microsoft Power BI usando los datos de Intune como fuente de datos principal
  4. Ver el estado de cumplimiento detallado de todos los dispositivos con las directivas de seguridad activas y sus niveles de riesgo en Microsoft Intune
Ver respuesta

Respuesta correcta: B. Advanced Analytics ofrece análisis predictivos (identificar dispositivos propensos a fallos antes de que fallen), análisis de experiencia de usuario, consultas KQL en tiempo real y análisis de anomalías que no están en los informes estándar.

6. Un administrador necesita obtener la clave de recuperación de BitLocker de un dispositivo Windows inscrito en Intune. ¿Dónde puede encontrarla en el portal de Intune?

  1. Seguridad de puntos de conexión > Directivas de cifrado de disco
  2. Dispositivos > seleccionar el dispositivo > Claves de recuperación
  3. Informes > Cifrado de dispositivos
  4. Microsoft Entra ID > Dispositivos > seleccionar el dispositivo > Claves de BitLocker
Ver respuesta

Respuesta correcta: B. En el portal de Intune, navegando a Dispositivos > seleccionar el dispositivo específico > Claves de recuperación, el administrador puede ver la clave de recuperación de BitLocker almacenada en Intune.

7. ¿Qué lenguaje de consulta se utiliza para ejecutar consultas de dispositivos (Device query) en Intune Advanced Analytics?

  1. SQL (Lenguaje de consulta estructurado) con extensiones para Microsoft Azure Monitor
  2. KQL (Lenguaje de consulta de Kusto)
  3. PowerShell con módulos de Microsoft Graph para consultas de inventario de dispositivos
  4. OData con filtros REST para consultas de propiedades de dispositivos en Intune
Ver respuesta

Respuesta correcta: B. Las consultas de dispositivos en Intune Advanced Analytics utilizan KQL (Kusto Query Language), el mismo lenguaje usado en Microsoft Defender, Azure Monitor y otros servicios de Microsoft.

8. ¿Qué acción remota de Intune permite obtener el inventario de software instalado, procesos en ejecución y configuración del registro de un dispositivo Windows específico en tiempo real?

  1. Recopilar diagnósticos (Collect diagnostics) para descargar los archivos de registro del dispositivo
  2. Consulta de dispositivo (Device query) usando KQL en Intune Advanced Analytics
  3. Ejecutar un script de PowerShell de inventario de software predefinido desde la sección de scripts de Intune
  4. Sincronizar el dispositivo y ver las propiedades detalladas de hardware en la sección de propiedades del portal
Ver respuesta

Respuesta correcta: B. La consulta de dispositivo (Device query) con KQL en Advanced Analytics permite consultar en tiempo real el estado de un dispositivo: software instalado, procesos, servicios, claves de registro, usuarios locales, y mucho más.

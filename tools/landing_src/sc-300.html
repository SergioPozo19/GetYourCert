Guía de estudio de SC-300: qué entra y cómo prepararlo

SC-300 study guide: what's covered and how to prepare

SC-300 es el examen de administrador de identidades y accesos con Microsoft Entra. Las preguntas piden la opción más segura que cumpla el requisito, y suelen mezclar acceso condicional, métodos de autenticación y gobernanza.

SC-300 is the identity and access administrator exam with Microsoft Entra. Questions ask for the most secure option that meets the requirement, and often mix Conditional Access, authentication methods and governance.

User identities (20-25%)

  • Usuarios, grupos dinámicos, unidades administrativas y licencias por grupo
  • Users, dynamic groups, administrative units and group-based licensing
  • Identidades híbridas: Entra Connect, Cloud Sync, PHS, PTA y federación
  • Hybrid identity: Entra Connect, Cloud Sync, PHS, PTA and federation
  • Identidades externas: B2B, colaboración entre inquilinos y External ID
  • External identities: B2B, cross-tenant collaboration and External ID
  • Dominios personalizados y configuración del inquilino
  • Custom domains and tenant settings

Autenticación y acceso (25-30%)

Authentication and access (25-30%)

  • Métodos de autenticación: Authenticator, FIDO2, claves de acceso, Windows Hello y TAP
  • Authentication methods: Authenticator, FIDO2, passkeys, Windows Hello and TAP
  • Directivas de acceso condicional, condiciones, controles y modo de solo informe
  • Conditional Access policies, conditions, controls and report-only mode
  • Protección de identidades: riesgo de usuario y de inicio de sesión
  • Identity Protection: user and sign-in risk
  • Global Secure Access y acceso a aplicaciones privadas

  • Defender for Cloud Apps para aplicaciones en la nube
  • Defender for Cloud Apps for cloud apps

  • Entitlement management: access packages and catalogs

Confusiones típicas en el examen

Common exam traps

Registro de aplicación frente a aplicación empresarial

App registration vs enterprise application

El registro de aplicación define la aplicación (una sola vez, en su inquilino de origen); la aplicación empresarial es su entidad de servicio en cada inquilino donde se usa, y ahí se asignan usuarios y SSO.

The app registration defines the app (once, in its home tenant); the enterprise application is its service principal in each tenant where it is used, and that's where you assign users and SSO.

Riesgo de usuario frente a riesgo de inicio de sesión

User risk vs sign-in risk

El riesgo de inicio de sesión valora un intento concreto (ubicación rara, IP anónima); el riesgo de usuario indica que la cuenta puede estar comprometida (credenciales filtradas).

Sign-in risk scores a single attempt (unusual location, anonymous IP); user risk means the account itself may be compromised (leaked credentials).

Paquete de acceso frente a revisión de acceso

Access package vs access review

El paquete de acceso da un conjunto de permisos bajo solicitud y con caducidad; la revisión de acceso comprueba periódicamente si quien tiene el acceso aún lo necesita.

An access package grants a bundle of permissions on request with expiry; an access review periodically checks whether people who have access still need it.

Identidad administrada asignada por el sistema o por el usuario

System-assigned vs user-assigned managed identity

La del sistema va unida a un recurso y se borra con él; la del usuario es un recurso independiente que puedes compartir entre varios.

A system-assigned identity is tied to one resource and is deleted with it; a user-assigned identity is a standalone resource you can share across several.

Guía de estudio de AZ-305: qué entra y cómo prepararlo

AZ-305 study guide: what's covered and how to prepare

AZ-305 es el examen de arquitecto de soluciones de Azure. No pregunta cómo configurar algo, sino qué servicio elegir para unos requisitos de coste, disponibilidad, seguridad y rendimiento. Se da por hecho que ya sabes lo de AZ-104.

AZ-305 is the Azure solutions architect exam. It doesn't ask how to configure something but which service to choose for given cost, availability, security and performance requirements. It assumes you already know AZ-104 material.

Confusiones típicas en el examen

Common exam traps

Front Door, Application Gateway, Traffic Manager y Load Balancer

Front Door vs Application Gateway vs Traffic Manager vs Load Balancer

Front Door es global y HTTP(S); Application Gateway es regional y HTTP(S) con WAF; Traffic Manager es global por DNS para cualquier protocolo; Load Balancer es regional en la capa 4.

Front Door is global and HTTP(S); Application Gateway is regional HTTP(S) with WAF; Traffic Manager is global DNS-based for any protocol; Load Balancer is regional at layer 4.

Service Bus, Event Grid y Event Hubs

Service Bus vs Event Grid vs Event Hubs

Service Bus es mensajería empresarial con colas, temas y orden; Event Grid reparte eventos discretos a suscriptores; Event Hubs ingiere flujos de telemetría a gran escala.

Service Bus is enterprise messaging with queues, topics and ordering; Event Grid distributes discrete events to subscribers; Event Hubs ingests large-scale telemetry streams.

SQL Database frente a Managed Instance

SQL Database vs Managed Instance

SQL Database es una base de datos PaaS individual o en grupo elástico; Managed Instance da casi toda la compatibilidad de SQL Server (Agente SQL, consultas entre bases de datos) para migrar sin cambios.

SQL Database is a single PaaS database or elastic pool; Managed Instance offers near-full SQL Server compatibility (SQL Agent, cross-database queries) for lift-and-shift migrations.

RPO frente a RTO

RPO vs RTO

El RPO es cuántos datos puedes perder (distancia a la última copia); el RTO es cuánto tiempo puedes estar sin servicio hasta recuperarte.

RPO is how much data you can lose (time since the last copy); RTO is how long you can be down before you recover.

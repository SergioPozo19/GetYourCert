1. En una plantilla ARM, una cuenta de almacenamiento debe crearse antes que una máquina virtual que utiliza su contenedor de diagnósticos. ¿Qué elemento de la plantilla se usa para declarar explícitamente esa dependencia?

  1. outputs
  2. parameters
  3. apiVersion
  4. dependsOn
Ver respuesta

Respuesta correcta: D. La propiedad 'dependsOn' dentro de la definición de un recurso indica a Azure Resource Manager que ese recurso debe esperar a que se complete el despliegue de los recursos listados antes de desplegarse.

2. Una aplicación requiere discos de máquina virtual con el mayor rendimiento posible (IOPS y throughput muy altos, latencia submilisegundo) para una base de datos transaccional crítica. ¿Qué tipo de disco administrado deberías elegir?

  1. No existen diferencias de rendimiento entre tipos de disco
  2. Standard HDD
  3. Disco Ultra (Ultra Disk)
  4. Standard SSD
Ver respuesta

Respuesta correcta: C. Los discos Ultra ofrecen el mayor rendimiento disponible en Azure, con IOPS y throughput configurables de forma independiente y latencia consistentemente baja (submilisegundo), ideales para cargas de trabajo con requisitos de E/S muy exigentes.

3. Un administrador necesita cambiar el tamaño de una máquina virtual a una serie con más vCPU y memoria. La nueva serie no está disponible en el clúster de hardware donde se encuentra la VM. ¿Qué puede ocurrir?

  1. Es posible que la VM deba detenerse (y posiblemente reasignarse a otro hardware) para completar el cambio de tamaño
  2. El cambio de tamaño siempre es instantáneo sin reinicio, sin excepciones, incluso entre series distintas
  3. Nunca es posible cambiar el tamaño de una VM una vez creada, hay que crear una nueva
  4. Cambiar el tamaño elimina automáticamente todos los discos de datos adjuntos a la VM
Ver respuesta

Respuesta correcta: A. Algunos cambios de tamaño se pueden hacer sin detener la VM si el hardware actual admite el nuevo tamaño; pero si el nuevo tamaño no está disponible en el clúster actual, la VM debe detenerse para reasignarse a hardware compatible antes de aplicar el nuevo tamaño.

4. ¿Cuál es el propósito principal de Azure Dedicated Host?

  1. Proporcionar servidores físicos dedicados para una sola organización, cumpliendo requisitos de aislamiento y conformidad normativa.
  2. Ofrecer máquinas virtuales de serie HB y HC con acceso directo a GPU NVIDIA A100 para cargas de trabajo de IA y HPC.
  3. Reducir costes al compartir hardware físico entre múltiples clientes en un modelo de tenencia aislada con SLA de nivel Premium.
  4. Permitir a los clientes instalar hipervisores de terceros como KVM o Xen sobre la infraestructura bare metal de Azure.
Ver respuesta

Respuesta correcta: A. Azure Dedicated Host proporciona servidores físicos dedicados exclusivamente a una organización. Se usan cuando los requisitos de conformidad normativa exigen aislamiento a nivel de hardware, control sobre el mantenimiento del host y visibilidad de los servidores subyacentes. Se organizan en Host Groups.

5. ¿Qué servicio de Azure proporciona un registro privado para almacenar y administrar imágenes de contenedor Docker y artefactos OCI?

  1. Azure Container Registry (ACR)
  2. Azure Functions con plan de consumo para ejecución de contenedores sin servidor de corta duración
  3. Azure Container Instances (ACI) para ejecución de contenedores aislados sin necesidad de orquestador
  4. Azure Container Apps con escalado KEDA basado en eventos para aplicaciones de microservicios
Ver respuesta

Respuesta correcta: A. Azure Container Registry (ACR) es un registro privado y administrado para imágenes de contenedor Docker y otros artefactos compatibles con OCI, que se integra con servicios de cómputo como AKS, ACI o App Service.

6. Al actualizar un clúster de AKS, ¿cuál es el orden correcto de actualización de los componentes?

  1. Primero el plano de control (control plane) y luego los pools de nodos.
  2. Primero los pools de nodos y luego el plano de control.
  3. Los pools de nodos y el plano de control se actualizan simultáneamente.
  4. Solo se actualiza el plano de control; los nodos se recrean automáticamente.
Ver respuesta

Respuesta correcta: A. En AKS, la actualización siempre comienza por el plano de control (servidor de API, etcd, scheduler) y después se actualizan los pools de nodos de forma gradual (rolling upgrade). Esto garantiza que el plano de control sea siempre igual o superior en versión a los nodos.

7. ¿Qué característica de AKS permite que diferentes pools de nodos usen diferentes tamaños de VM para adaptar el hardware a los distintos tipos de carga de trabajo?

  1. Los pools de nodos múltiples (multiple node pools) con distintos tamaños de VM por pool.
  2. El Cluster Autoscaler con perfiles de tamaño definidos por el usuario.
  3. Las etiquetas de nodo (node labels) que permiten seleccionar tamaños dinámicamente.
  4. Los taints y toleraciones de Kubernetes que determinan el tamaño de VM del nodo.
Ver respuesta

Respuesta correcta: A. AKS admite múltiples pools de nodos, cada uno con su propio tamaño de VM, sistema operativo y configuración de escalado. Por ejemplo, un pool del sistema puede usar VMs de propósito general (D-series) y un pool de usuario para ML puede usar VMs con GPU (N-series), todo dentro del mismo clúster.

8. ¿Para qué tipo de dominio de App Service NO se puede utilizar un registro CNAME en la configuración de DNS?

  1. Dominio raíz (apex domain), como contoso.com sin prefijo.
  2. Subdominio de tercer nivel, como app.www.contoso.com.
  3. Subdominio estándar, como www.contoso.com.
  4. Subdominio con guiones, como my-app.contoso.com.
Ver respuesta

Respuesta correcta: A. El estándar DNS RFC 1912 prohíbe el uso de CNAME en el vértice de una zona DNS (dominio raíz como 'contoso.com'), ya que ese registro debe coexistir con los registros SOA y NS. Para dominios apex, se usa un registro A (que apunta a la IP) junto con un registro TXT para la verificación de propiedad.

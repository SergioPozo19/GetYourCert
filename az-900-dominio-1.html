AZ-900 · Dominio 1 de 3 · 25-30% del examen

Descripción de los conceptos de la nube

El dominio 1 de AZ-900 supone entre el 25 y el 30% del examen. En EarnYourCert tienes 132 preguntas originales de este dominio, todas con explicación: 85 de opción múltiple, 27 de sí o no y 20 de completar u ordenar, como en el examen real.

Practicar el dominio 1 gratis →Sin registro. Elige cuántas preguntas quieres hacer.

Qué entra en este dominio

  • Modelo de responsabilidad compartida en IaaS, PaaS y SaaS
  • Nube pública, privada e híbrida
  • Gasto de capital (CapEx) frente a gasto operativo (OpEx) y pago por consumo
  • Alta disponibilidad, escalabilidad, elasticidad y fiabilidad

Preguntas de ejemplo del dominio 1

8 preguntas de nuestro banco de 132 para este dominio. Intenta responder antes de ver la solución.

1. ¿Qué característica de la nube hace referencia a que los recursos sean accesibles a través de la red desde distintos tipos de dispositivos, como portátiles o móviles?

  1. Gobernanza centralizada
  2. Acceso amplio a la red
  3. Dependencia del proveedor
  4. Economía de escala
Ver respuesta

Respuesta correcta: B. El acceso amplio a la red hace referencia a que los recursos en la nube estén disponibles a través de la red y se pueda acceder a ellos mediante mecanismos estándar desde distintos tipos de dispositivos.

2. ¿Qué ventaja describe mejor el hecho de que un cliente pueda crear una cuenta y empezar a usar servicios de Azure sin firmar un contrato previo a largo plazo?

  1. Bajo coste de entrada y autoservicio inmediato
  2. Necesidad de aprobación gubernamental previa
  3. Obligación de comprar hardware físico primero
  4. Requisito de contratar un Contrato Enterprise
Ver respuesta

Respuesta correcta: A. La posibilidad de crear una cuenta y empezar a usar servicios de inmediato, sin contratos a largo plazo ni grandes inversiones iniciales, reduce el coste de entrada y permite experimentar rápidamente.

3. ¿Qué término describe la capacidad de un sistema para seguir funcionando correctamente incluso cuando uno o más de sus componentes fallan?

  1. Tolerancia a errores
  2. Facturación granular por recurso y por hora
  3. Gobernanza mediante directivas de Azure Policy
  4. Previsibilidad del rendimiento y del coste
Ver respuesta

Respuesta correcta: A. La tolerancia a errores es la capacidad de un sistema para seguir operando correctamente a pesar del fallo de uno o más de sus componentes, normalmente mediante redundancia y diseño resiliente.

4. ¿Cómo ayuda la elasticidad de la nube a evitar el sobreaprovisionamiento de recursos para picos de tráfico poco frecuentes?

  1. Elimina por completo la necesidad de medir el tráfico
  2. Obliga a mantener siempre la capacidad máxima posible
  3. Requiere comprar servidores adicionales de forma permanente
  4. Añade capacidad solo en picos y la reduce después
Ver respuesta

Respuesta correcta: D. La elasticidad permite añadir capacidad adicional solo durante los picos de demanda y reducirla cuando ya no es necesaria, evitando pagar por recursos sobredimensionados el resto del tiempo.

5. ¿Cómo reduce la nube la necesidad de que una organización mantenga un segundo centro de datos físico exclusivamente para recuperación ante desastres?

  1. Elimina por completo la necesidad de copias de seguridad
  2. Permite replicar datos en otra región a demanda
  3. Requiere duplicar el personal de TI permanentemente
  4. Obliga a construir un segundo edificio idéntico
Ver respuesta

Respuesta correcta: B. La nube permite replicar datos y cargas de trabajo en otra región a demanda, sin necesidad de construir y mantener un segundo centro de datos físico exclusivamente para recuperación ante desastres.

6. Una empresa necesita una base de datos NoSQL distribuida globalmente, con baja latencia garantizada y escalado automático, sin tener que instalar ni administrar ningún motor de base de datos. ¿Qué servicio de Azure y qué modelo de servicio se ajustan mejor a este requisito?

  1. Azure Cosmos DB, un servicio PaaS de base de datos totalmente gestionado
  2. Una máquina virtual con MongoDB instalado manualmente, como ejemplo de IaaS
  3. Microsoft 365, como ejemplo de SaaS para almacenamiento de datos
  4. Azure Functions, como ejemplo de FaaS para almacenar datos de forma persistente
Ver respuesta

Respuesta correcta: A. Azure Cosmos DB es un servicio de base de datos NoSQL totalmente gestionado (PaaS), que ofrece distribución global, baja latencia garantizada mediante SLA y escalado automático, sin que el cliente tenga que instalar ni administrar un motor de base de datos. Una máquina virtual con MongoDB instalado manualmente sería un enfoque IaaS, donde el cliente tendría que gestionar el motor de base de datos, justo lo que se quiere evitar. Microsoft 365 es una suite de productividad SaaS, no un servicio de base de datos. Y Azure Functions es un servicio de computación sin servidor para ejecutar código, no está diseñado como almacén de datos persistente principal.

7. Una empresa está decidiendo entre alojar su sitio web en una máquina virtual (IaaS) o en Azure App Service (PaaS). Si eligen App Service, ¿cuál de las siguientes tareas seguirá siendo SIEMPRE responsabilidad de la empresa, independientemente del modelo elegido?

  1. La configuración de la red física del centro de datos donde se aloja el servicio de Azure App Service
  2. El mantenimiento físico y lógico de los servidores subyacentes donde se ejecuta el Plan de App Service de Azure
  3. La aplicación de parches de seguridad al sistema operativo subyacente que Azure App Service gestiona automáticamente
  4. El código de la aplicación, su configuración específica y la gestión de los datos que maneja
Ver respuesta

Respuesta correcta: D. Independientemente de si se usa IaaS o PaaS, el cliente siempre es responsable del código de su aplicación, su configuración específica y los datos que maneja, ya que estos elementos son exclusivos del cliente en ambos modelos. La aplicación de parches al sistema operativo es responsabilidad del cliente en IaaS, pero de Microsoft en PaaS, por lo que no es constante. El mantenimiento físico de los servidores siempre es responsabilidad de Microsoft, en cualquier modelo. Y la configuración de la red física del centro de datos también es siempre responsabilidad de Microsoft, el cliente nunca gestiona esa capa.

8. Una empresa de seguros utiliza SharePoint Online dentro de Microsoft 365 para gestionar documentos internos. Un nuevo empleado pregunta si la empresa necesita gestionar las actualizaciones de seguridad del servidor que ejecuta SharePoint. ¿Cuál es la respuesta correcta?

  1. No, porque la empresa no tiene ningún tipo de responsabilidad sobre la seguridad al usar SharePoint Online
  2. Sí, porque en cualquier servicio basado en la nube el cliente siempre debe aplicar las actualizaciones del servidor
  3. No, porque SharePoint Online es un servicio SaaS y Microsoft gestiona toda la infraestructura y las actualizaciones del servidor
  4. Sí, pero solo si la empresa eligió un plan de Microsoft 365 de nivel básico
Ver respuesta

Respuesta correcta: C. SharePoint Online es un servicio SaaS dentro de Microsoft 365, lo que significa que Microsoft se encarga de toda la infraestructura subyacente, incluyendo el sistema operativo, el servidor y sus actualizaciones de seguridad. No es cierto que el cliente siempre deba aplicar actualizaciones de servidor en cualquier servicio en la nube, eso varía según el modelo (es cierto en IaaS, pero no en SaaS). La empresa sí tiene responsabilidades de seguridad, como la gestión de identidades, permisos y clasificación de los documentos, aunque no sobre la infraestructura del servidor. Y esta gestión por parte de Microsoft no depende del nivel de plan contratado, es inherente al modelo SaaS.

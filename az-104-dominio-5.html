Preguntas de ejemplo del dominio 5

8 preguntas de nuestro banco de 111 para este dominio. Intenta responder antes de ver la solución.

1. Azure Update Manager es la solución más reciente para gestionar actualizaciones del sistema operativo. ¿Cuál es una característica clave que la diferencia de Update Management de Azure Automation?

  1. Requiere una cuenta de Azure Automation y un área de trabajo de Log Analytics vinculada para gestionar actualizaciones de Windows y Linux
  2. Admite tanto VMs de Azure como servidores habilitados para Arc sin necesidad de cuenta de Automation
  3. Solo es compatible con máquinas virtuales Windows Server 2019 y 2022; las distribuciones Linux no son compatibles con este servicio
  4. Necesita el agente MMA (Microsoft Monitoring Agent) o el agente OMS instalado en cada VM para recopilar datos de actualización
Ver respuesta

Respuesta correcta: B. Azure Update Manager es una solución nativa que no depende de una cuenta de Azure Automation ni de un área de trabajo de Log Analytics. Admite VMs de Azure y servidores habilitados para Azure Arc, lo que lo hace más flexible y sencillo de implementar que la solución de Update Management anterior.

2. Un administrador revisa las recomendaciones de Azure Advisor y quiere entender en qué categoría aparecerán las sugerencias para reducir el coste de los recursos infrautilizados.

  1. Rendimiento
  2. Confiabilidad
  3. Coste
  4. Excelencia operativa
Ver respuesta

Respuesta correcta: C. Azure Advisor organiza las recomendaciones en cinco categorías: Coste, Seguridad, Confiabilidad, Rendimiento y Excelencia operativa. Las sugerencias para reducir el gasto en recursos infrautilizados, como redimensionar o apagar VMs, aparecen en la categoría 'Coste'.

3. Un administrador necesita que las alertas de Azure Monitor sobre un entorno de producción no generen notificaciones durante la ventana de mantenimiento nocturno (de 23:00 a 06:00 los sábados). ¿Cuál es la forma más eficiente de lograrlo?

  1. Deshabilitar y volver a habilitar manualmente cada regla de alerta antes y después del mantenimiento
  2. Crear una regla de procesamiento de alertas con supresión de notificaciones para esa ventana de tiempo
  3. Eliminar el grupo de acciones durante el mantenimiento y recrearlo después
  4. Configurar una alerta de registro de actividad para suprimir otras alertas
Ver respuesta

Respuesta correcta: B. Las reglas de procesamiento de alertas permiten configurar la supresión de notificaciones para ventanas de tiempo recurrentes o únicas sin modificar las reglas de alerta. Es la forma recomendada de gestionar el silencio de alertas durante mantenimientos, ya que las reglas de alerta siguen evaluándose pero las notificaciones se suprimen.

4. Después de una conmutación por error (failover) con Azure Site Recovery hacia una región secundaria, y una vez resuelto el problema en la región principal, ¿qué operación permite volver a ejecutar las cargas de trabajo en la región original?

  1. Restablecimiento de fábrica
  2. Conmutación de vuelta (Failback)
  3. Eliminación del almacén
  4. Replicación geo-redundante automática
Ver respuesta

Respuesta correcta: B. La conmutación de vuelta (failback) es el proceso de volver a replicar los cambios realizados en la región secundaria de vuelta a la región principal original y conmutar las cargas de trabajo de nuevo a esa región una vez que está disponible.

5. ¿Qué nivel de redundancia de almacenamiento de Azure Backup mantiene tres copias de los datos dentro de una sola región, protegiendo frente a fallos de hardware pero no frente a una interrupción regional completa?

  1. Almacenamiento redundante local (LRS)
  2. Almacenamiento con redundancia entre zonas (ZRS) únicamente en escenarios geo-replicados
  3. Sin redundancia
  4. Almacenamiento geo-redundante (GRS)
Ver respuesta

Respuesta correcta: A. El almacenamiento redundante local (LRS) replica los datos de copia de seguridad tres veces dentro de un único centro de datos de la región, protegiendo frente a fallos de hardware (disco, nodo, rack) pero no frente a la pérdida de toda la región.

6. Una empresa necesita hacer copias de seguridad de un recurso compartido de Azure Files. ¿Cómo funciona el mecanismo de copia de seguridad de Azure Backup para Azure Files?

  1. Copia los archivos a una cuenta de almacenamiento de copia de seguridad dedicada en otra región
  2. Utiliza instantáneas de recurso compartido (share snapshots) almacenadas en la misma cuenta de almacenamiento
  3. Requiere el agente MARS instalado en un servidor Windows para copiar los archivos
  4. Convierte el recurso compartido SMB a un disco gestionado y realiza una copia de seguridad a nivel de bloque
Ver respuesta

Respuesta correcta: B. Azure Backup para Azure Files utiliza instantáneas de recurso compartido (share snapshots), que son copias incrementales almacenadas en la misma cuenta de almacenamiento que el recurso compartido. El Recovery Services vault mantiene los metadatos de los puntos de recuperación, pero los datos reales permanecen en la cuenta de almacenamiento.

7. En una directiva de replicación de ASR para VMs de Hyper-V, ¿cuáles son las frecuencias de replicación disponibles?

  1. Cada 1 minuto, 5 minutos o 15 minutos
  2. Cada 30 segundos, 5 minutos o 15 minutos
  3. Cada 1 hora, 4 horas o 24 horas
  4. Cada 5 minutos o 30 minutos
Ver respuesta

Respuesta correcta: B. Para VMs de Hyper-V replicadas con ASR, las frecuencias de replicación disponibles son 30 segundos, 5 minutos y 15 minutos. Cuánto menor sea la frecuencia de replicación, menor será el RPO potencial, pero mayor el uso de ancho de banda y el impacto en el rendimiento.

8. El agente de movilidad (Mobility Service) es un componente requerido por Azure Site Recovery. ¿Para qué tipos de máquinas se requiere?

  1. Solo para VMs de Hyper-V replicadas a Azure desde un host Hyper-V administrado por System Center VMM
  2. Para servidores físicos y VMs de VMware que se replican a Azure
  3. Para VMs de Azure que se replican de una región primaria a una región secundaria de Azure como destino de DR
  4. Para cualquier VM que use el agente MARS (Microsoft Azure Recovery Services) en la copia de seguridad con Azure Backup
Ver respuesta

Respuesta correcta: B. El agente de movilidad (Mobility Service) debe instalarse en cada servidor físico o VM de VMware que se vaya a replicar a Azure mediante ASR. Captura las escrituras de datos del servidor y las reenvía al servidor de procesos de ASR. Para VMs de Hyper-V y VMs de Azure entre regiones, el mecanismo de replicación es diferente y no requiere el agente de movilidad.
